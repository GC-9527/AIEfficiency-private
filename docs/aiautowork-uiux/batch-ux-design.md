# 100 条批量任务 UX 设计

## 目标

让用户处理“例外”，而不是逐条批准 100 次。

## Demo 数据分布

- 原始输入：100
- 重复：3
- 无效：2
- 有效：95
- 自动通过：68
- 建议批量确认：17
- 需要人工介入：8
- 达到最大修复次数：2

## 页面原则

1. 默认只显示 27 条异常和建议确认项。
2. 68 条自动通过折叠在状态分布中。
3. 使用紧凑表格，不使用 100 个大卡片。
4. 详情、证据和候选版本在 Drawer 中渐进展开。
5. 行级更新不导致整表重排。
6. 第一列、任务摘要和状态列固定。

## 三层自动分流

### 自动就绪

条件：

- 综合评分达到阈值。
- 所有关键字段达到最低阈值。
- 自检和独立复核通过。
- 无阻断。

交互：无需逐条确认，可直接进入批量预检。

### 建议批量确认

条件：

- 配置完整，无阻断。
- 中等可信。
- 多条任务可共享公共字段。

交互：按配置签名分组，一次确认整组。

### 需要人工介入

条件：

- 主工程/仓库/分支/Flavor 缺失或冲突。
- 用户明确输入与 AI 推荐冲突。
- 关键字段低可信。
- 三次自动修复失败。

交互：只显示异常字段，支持批量补全。

## 配置分组

配置签名包含：

- 主工程
- 主仓库
- 依赖工程集合
- 目标 Flavor
- Build Type
- 执行模式
- 测试策略

不包含目标分支，因为每个任务的分支可不同。

组确认文案示例：

> 将为 18 个任务采用相同的主工程、主仓库、依赖工程和目标 Flavor；各任务保留自己的目标分支。

操作：

- 采纳整组
- 修改公共字段
- 查看组内差异
- 移出某项
- 单项覆盖

## 批量人工补全

支持公共字段：

- 主工程
- 主仓库
- Base Branch
- 依赖工程
- 目标 Flavor
- Build Type
- 执行模式
- 测试策略

独立字段默认不批量覆盖：

- 目标分支
- Commit/MR/PR
- TB 单号
- 用户锁定值

## 批量操作条

选择任务后显示：

> 已选择 18 个任务

操作：

- 重新推导
- 批量应用共同配置
- 批量补全
- 批量预检
- 忽略
- 移出批次

每次操作必须显示影响数量。

## 性能体验

正式实现建议：

- 50 行分页或虚拟滚动。
- 服务端筛选、排序和状态聚合。
- 行状态局部更新。
- Drawer 延迟加载完整证据和版本历史。
- 搜索防抖 250ms。
- 保留选择状态，不因状态更新丢失。

Mock Demo 使用本地 100 条数组模拟。

## 创建与执行

创建完成结果独立展示：

- 已创建：100
- 创建失败：0（部分失败场景为 94/95）
- 正在执行：5
- 等待执行：95

创建故事点不会绕过执行并发。

## 失败恢复

- 保留成功项。
- “重试失败项”只操作失败行。
- 失败原因按可修复/需人工/不可重试分类。
- 部分成功 Banner 不覆盖主表。
- 用户可导出失败摘要，但 Demo 不生成真实文件。
