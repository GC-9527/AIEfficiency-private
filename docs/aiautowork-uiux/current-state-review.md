# 当前前端与 DevBench 现状评审

## 技术栈

- React 19、React DOM 19。
- React Router DOM 7，`main.jsx` 使用懒加载路由。
- Vite 6。
- Tailwind CSS 3.4、PostCSS、Autoprefixer。
- 未使用 Ant Design、MUI、Chakra、Radix 等企业组件库。
- 未使用独立图标包，主要是内联 SVG，部分旧界面仍含 Emoji。
- 流程图能力来自 `@xyflow/react` 和 `@dagrejs/dagre`。

## 全局 Layout 与导航

`App.jsx` 使用固定高度桌面布局：

- 左侧全局导航宽度 180px，可收起到 56px。
- 主内容区 `flex-1 + overflow-hidden`。
- 深色背景：`#0f0f10` / `#18181b`。
- 全局导航活跃态：`bg-zinc-700 text-white`。
- 菜单项高度 40px，图标约 20px。

问题：

1. 一级导航超过 15 项，研发相关入口分散。
2. DevBench、TB 任务、项目开发、Bug 分析等入口在同一层，没有任务域聚合。
3. 图标来源和风格不完全统一。
4. 全局导航适合工具集合，不适合承载新的复杂工作台内部结构。

## 视觉体系

可复用基线：

- Zinc 灰阶和深色工作台基调。
- 11–14px 高信息密度字号。
- 1px 边框、6–12px 圆角。
- 蓝色作为导航和主交互色。
- Emerald/Green 表示成功和运行。
- Amber 表示等待人工或风险。
- Rose/Red 表示失败与阻断。
- Sticky 表头、紧凑表格、固定侧栏。

需要改进：

- 状态颜色没有统一语义表。
- 大量局部 `bg-zinc-*` 拼装，缺少设计 Token。
- 按钮层级不稳定，同一行有时出现多个同权按钮。
- Loading、Empty、Error 多为零散文本。
- 个别旧组件使用 Emoji 作为正式图标。

## DevBench 页面结构

当前 `/devbench` 包含：

- 顶部“故事点 / AI 训练”切换。
- 故事点会话 Tab，支持运行灯、切换、关闭、分组。
- 单故事点完整对话和工作流。
- 任务面板：待办、TB 候选、任务组。
- 新建故事点、TB 入口、Git commit 单个/批量评审入口。
- 工程配置、设备、构建、Git、发布、报告等工具。
- 配置推导复核、AI 训练、RAG 证据治理。

实时页面在评审时存在两个打开故事点：

- `CARB-13465`：验证中，绑定设备。
- `CARB-13888`：修复中。

## 可复用能力

1. TB 单号、纯数字和任务链接的输入心智。
2. 待办、TB 候选、故事点的一对一关联。
3. 故事点 Tab 的运行灯、切换、关闭和恢复。
4. 工作流阶段和运行状态的现有数据。
5. `ConfigInferenceReview` 的多来源证据、工程/仓库/分支/Flavor 编辑。
6. Git commit 模糊匹配、歧义候选和批量解析。
7. Portal 弹窗、高层级遮罩和独立滚动。
8. 自定义 EditableCombobox、RemoteBranchSelect 等领域组件。

## 当前 UX 主要问题

### 状态层级混杂

任务是否已创建、AI 是否运行、工作流走到哪一步、配置是否已确认常出现在同一区域，但缺少明确的状态分层。

### 入口分散

TB、待办、Git commit、故事点新建分别存在于不同按钮或面板，用户必须先理解功能位置。

### 配置审核过重

现有配置复核功能强，但信息量大，AI 建议、最终值、证据、治理状态和本地工程匹配同时展开，普通用户难以快速定位阻断项。

### 批量能力局部化

Git commit 已有批量解析，但缺少跨 TB、手工、Git Review 的统一批次和异常优先处理。

### 工作台和深度开发混在一起

DevBench 同时承担总入口和单故事点工作区，导致顶部工具、任务面板、会话 Tab 和开发内容竞争空间。

### 导航扩展风险

继续把批量、待确认、设置等都做成全局一级菜单会进一步膨胀现有侧栏。

## 设计结论

- 保留现有深色 Zinc 视觉基线和高密度桌面风格。
- 新增 AI 工作台产品域，在域内建立四个一级入口。
- DevBench 退回单故事点深度工作区。
- 重构配置审核为“AI 推荐 / 最终值 / 状态 / 证据”逐字段差异。
- 批量处理默认只展示异常，自动通过折叠。
- 建立统一状态 Token、按钮层级、空状态和 Loading 规范。
