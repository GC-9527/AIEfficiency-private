# 可信度与就绪评分设计

## 设计目标

避免单一“AI 自信度 95%”误导用户。评分用于分流和解释风险，不代表真实正确率。

## 七类信号

| 信号 | 含义 | 主列表 |
|---|---|---|
| AI 推导可信度 | 模型对候选值的概率性判断 | 详情 |
| 证据覆盖度 | 可验证来源是否覆盖关键字段 | 详情 |
| 确定性自检 | 仓库、分支、Flavor 等规则校验 | 显示 |
| 独立复核一致性 | 第二 Reviewer 是否一致 | 详情 |
| 元数据有效性 | ID、分支、映射、枚举是否存在 | 详情 |
| 综合就绪评分 | 多信号组合后的排序值 | 显示 |
| 关键字段最低分 | 最弱关键字段 | 强制显示 |

## 主列表表达

紧凑显示：

```text
就绪 92
最低 42 · 目标分支
自检：阻断 1
```

如果最低关键分低于阈值，即使综合分高，也显示“关键字段低可信”，不能自动通过。

## 关键字段评分

- 主工程
- 主仓库
- 目标分支
- Base Branch
- 依赖工程
- 依赖分支
- 目标 Flavor
- Review Target
- 测试范围

## 分流规则

### 自动就绪

- 综合就绪评分 ≥ 88。
- 所有关键字段 ≥ 75。
- 自检通过。
- 独立复核一致。
- 无用户明确输入冲突。

### 建议批量确认

- 综合 70–87。
- 关键字段最低分 ≥ 60。
- 无阻断。
- 配置可分组。

### 人工介入

任一条件：

- 关键字段 < 60。
- 阻断 > 0。
- 用户输入冲突。
- 元数据无效。
- 三次自动修复失败。

## 字段详情

每个字段显示：

- AI 推荐值。
- 最终值。
- 字段评分。
- 来源：用户输入、TB 标签、历史成功、仓库映射、Flavor 关系、当前分支、训练配置版本。
- 自检结果。
- 是否锁定。
- 可验证证据摘要。

禁止展示思维链。

## 综合评分计算说明

UI 不展示复杂公式，只展示可理解解释：

> 综合就绪评分由证据覆盖、字段可信、自检、独立复核和元数据有效性共同计算。任何关键字段低于阈值都会阻止自动通过。

## 信息过载控制

- 主列表只显示综合分、最低分、自检。
- Hover 显示最低字段名称。
- Drawer 显示雷达式信号条，但不使用花哨图表。
- 字段级详情默认只展开异常和被用户覆盖项。
- 自动通过项的完整信号折叠。

## 候选版本比较

比较重点：

- 综合分变化
- 最低关键分变化
- 阻断变化
- 警告变化
- 修改字段
- 修复原因

高分版本不一定是最佳版本；用户锁定字段和明确输入优先于评分。
