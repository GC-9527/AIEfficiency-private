# devbench TB 工作流 — 使用与排障

> 面向 `/devbench` 工程开发工作台里「把一张 TB 单从待办做到完成」的端到端工作流：
> 半自动/全自动甄别、完整 TB 上下文、附件阈值下载、经验沉淀（经验库 / 工程 CLAUDE.md / Wiki / Bug Agent）。
>
> 实现：`gateway/routes/devbench.js`、`gateway/services/devbench/{index,store,tb-workflow,lessons}.js`、`web-dashboard/src/pages/devbench/`。

---

## 一、一句话流程

```
任务列表点「执行开发」              → 建/复用故事点 + 关联工单 + TB 状态 待处理→待确认
（半自动，默认）                    → 不自动分析；顶部状态条出现「待甄别」
确认工程/分支/flavor 已对齐         → 点「▶ 开始 AI 甄别」 或 直接发第一条消息
AI 甄别（读 TB 全字段 + 工程上下文） → 结论 IS_BUG / NOT_A_BUG
  ├─ IS_BUG  → 状态切「修复中」，后续轮真正改码 → 修复完成输出 FIX_DONE → 状态「可提测」+评论+附件
  └─ NOT_A_BUG → 醒目卡片，等用户点「确认拒绝」→ 状态「已拒绝」+评论+附件
完成/拒绝时                        → 经验自动入库 + 完成卡片可一键导出 Wiki / 工程 CLAUDE.md
```

---

## 二、快速上手（半自动，推荐）

1. **任务列表 →「执行开发」**：自动新建故事点（标题带 `#CARB-xxx#` 前缀）、关联工单、TB 状态 `待处理→待确认`。
   - 已开发过的任务按钮变「再次开发」，复用同一故事点（一对一绑定）。
2. **配置工程**：在故事点顶部选主工程（或「远程拉取」克隆指定车型/分支），选 flavor、绑定设备。
   - 远程拉取模式：点「开始初始化工程」克隆完成后才算「工程就绪」。
3. **开始分析**：顶部常驻状态条显示「待甄别」。两种触发方式：
   - 点 **「▶ 开始 AI 甄别」** 按钮；或
   - 直接在输入框**发第一条消息**（这条消息会作为甄别提问，自动先做甄别）。
4. **看甄别结论**：
   - **IS_BUG** → 状态条转「修复中」，继续对话让 Claude 改码；改完它会输出修复报告并把 TB 切「可提测」。
   - **NOT_A_BUG** → 聊天里弹醒目卡片「可能不是本侧问题」，**点「确认拒绝该 TB 单」** 才会真正改 TB 状态。
5. **完成后**：修复完成 / 确认拒绝的卡片上点 **「📚 加入 Wiki」** 或 **「📝 写入工程 CLAUDE.md」** 导出经验（经验已自动入库，这里是额外导出）。

## 三、半自动 vs 全自动

| | 半自动（默认 `semi`） | 全自动（预留 `full`） |
|---|---|---|
| 点「执行开发」 | 只流转 TB 状态，**不分析** | 工程就绪即**自动甄别** |
| 触发甄别 | 手动按钮 / 发第一条消息 | 自动 |
| 适用 | TB 单与工程配置尚未完全映射时（避免拉错/改错工程） | 待映射完善后再设默认 |

- 切换：状态条右侧「半自动 / 全自动」。**切到全自动有二次确认**（防误触发对错误工程自动跑）。
- 字段：`tab.workflow.autoMode`。后端网关：`POST /api/devbench/tabs/:id/workflow/auto-mode`。

> **「工程就绪」= 本地已配置工程，或远程分支已克隆到本地存在。点按钮/甄别都不会自动 `git clone/pull`**，
> 不会替你拉错工程或分支。要换分支请在故事点「Git 分支」处手动切。

## 四、甄别会读哪些上下文（每轮注入）

- **TB 单完整字段**：标题、描述、**回复评论（最近 30 条，解析出提单人与讨论文本）**、附件清单（名称+大小+是否可下载）。
- **备注图文**：富文本备注下载到 `docs/story/<slug>/archives/note.md` + 图片，可 `Read`。
- **工程上下文**：主工程路径 + **当前 git 分支** + 关联工程 + WebApp。
- **目标 flavor**（版本号）、**绑定设备**、**已附材料**。
- **历史经验库**：同 TB 项目既往单沉淀的「原因→预防」（见第六节）。

数据落点：`tab.tbContext`（标题/描述/评论/附件/projectId）、`tab.tbNote`（备注）。每次甄别都刷新，确保读到最新回复。

## 五、附件自动下载与阈值确认

- **阈值**（任一超过即需确认）：`数量 > 10` 或 `单个 > 20MB` 或 `合计 > 50MB`。
- **未超阈值**：甄别前**静默自动下载**到 `docs/story/<slug>/archives/`，Claude 可直接 `Read`。
- **超阈值**：不自动下，弹 **`AttachmentConfirmModal`** —— 勾选要下的附件 → 显示**合计大小**与**逐文件进度**（下载中 / ✓ / ✗）。下载中禁止关闭。
- 也可在配置区「TB 附件」手动逐个下载/刷新。
- 进度走 WebSocket `devbench_attach_progress`；批量下载 API：`POST /tabs/:id/tb-attachments/download-batch`。

## 六、工作流标记与经验沉淀

### AI 输出的隐藏标记（前端不可见，解析后剥离）
| 标记 | 含义 | 触发动作 |
|---|---|---|
| `<!-- TRIAGE: IS_BUG -->` | 是本侧问题 | 状态→`修复中` |
| `<!-- TRIAGE: NOT_A_BUG -->` | 非本侧问题 | 挂起待「确认拒绝」 |
| `<!-- FIX_DONE -->` | 修复完成 | 状态→`可提测` + 评论 + 附件 |
| `<!-- LESSON 原因:/预防:/关键词: -->` | 经验沉淀 | 入库（随 FIX_DONE / NOT_A_BUG 产出） |

### 经验沉淀（"写配置避免同类问题再次发生"）
修复完成 / 确认拒绝时自动落库，并在**后续同项目甄别/开发自动注入**（`buildLessonsContext`）：

| Sink | 何时写 | 永久性 | 备注 |
|---|---|---|---|
| **devbench 经验库** | 自动 | ✅ 永久 | 按 TB 项目隔离、团队共享，权威库（`store.{get,add,delete}Lessons`） |
| **工程 CLAUDE.md** | 完成卡片**按钮** | ✅ 永久 | 「已知问题与预防」托管块，Claude CLI 每次自动加载＝等价永久记忆。先读后写，只改托管块 |
| **工程 docs/wiki/** | 完成卡片**按钮** | ✅ 永久 | `docs/wiki/<slug>.md`，纳入 git |
| **Bug Agent 记忆** | 自动 best-effort | ⚠️ 7 天 TTL | `session_memory` 为近期记忆，非永久 |

> CLAUDE.md / Wiki 是 git 跟踪文件，所以做成**用户点按钮导出**（不静默改、不误提交），导出后请 review 再 commit。

## 七、排障 FAQ

**Q1：点「执行开发」后网页没任何反应，AI 没开始分析？**
半自动模式**本就不自动分析**。看顶部状态条：显示「待甄别」即正常 —— 点「▶ 开始 AI 甄别」或发一条消息。

**Q2：点「开始 AI 甄别」提示"工程未就绪"？**
主工程没选好，或远程拉取还没克隆完。先在配置区选本地主工程，或等「开始初始化工程」克隆完成。**系统不会替你自动拉取**。

**Q3：状态条一直「待甄别」，按钮点了没动静？**
- 有任务正在跑（同故事点串行，一次一轮）→ 等它结束或点「停止」。
- 已甄别过（phase 进入 fixing/reject_pending/testable/rejected）→ 不会重复甄别。
- 网关刚重启有残留运行态 → 再点一次即可（会自动清理残留）。

**Q4：附件没自动下载？**
- 超阈值（>10 / >20MB / >50MB）会弹窗让你勾选，不自动下 —— 在弹窗里选。
- 附件「不可下载」= 没有可用下载链接（权限/来源问题），属正常。
- 没弹窗也没下：确认是 TB 单故事点且备注/评论里确有附件；看网关日志 `devbench` 行。

**Q5：甄别结论是 NOT_A_BUG，但 TB 状态没变成「已拒绝」？**
设计如此 —— NOT_A_BUG 只是建议，**必须用户点卡片上「确认拒绝该 TB 单」** 才会改 TB 状态+写评论+附件。

**Q6：TB 状态/评论/附件同步失败？**
TB 写接口（状态流转/评论/附件上传）依赖真实接口，首次接入需联调；失败**不阻断本地流程**，卡片会如实提示「TB 同步失败，请手动处理」。按网关日志里的端点排查 Cookie/权限。

**Q7：经验没有在后续甄别里被参考？**
- 经验库按 **TB 项目** 隔离（`tab.tbContext.projectId`）。不同 TB 项目互不可见。
- 经验要等某张单**完成/拒绝**后才入库；新单甄别时才注入。
- 注入上限最近 20 条。

**Q8：点「写入工程 CLAUDE.md」后没看到变化？**
写的是**主工程根**的 `CLAUDE.md`（不是本仓库），在 `<!-- DEVBENCH_LESSONS_START/END -->` 托管块。打开主工程的 CLAUDE.md 查看；该文件改动需你自行 commit。

**Q9：全自动模式误触发了对错误工程的分析？**
切回半自动（状态条左侧）。全自动仅在确认 TB 单已完全映射工程配置后使用；切全自动时已有二次确认。

**Q10：改了网关代码 / 前端不生效？**
后端改动需**重启网关**；前端改动需**重建刷新**（开发模式 vite 热更，桌面版需重打包）。

## 八、速查

### 阈值 / 路径
- 附件阈值：`ATT_MAX_COUNT=10`、`ATT_MAX_ONE=20MB`、`ATT_MAX_TOTAL=50MB`（`gateway/routes/devbench.js`）。
- 存档：`<主工程>/docs/story/<slug>/ask/<slug>.txt`；附件/备注/报告：`docs/story/<slug>/archives/`；Wiki：`docs/wiki/<slug>.md`。
- 经验库存储：SQLite `devbench_userdata` 的共享行 `__devbench_shared__/shared`，按 `byProject.<TB项目id>.lessons` 隔离；`configs/market-projects.json` 仅作只读启动种子。

### 关键 API（`/api/devbench`）
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/tabs/:id/workflow/start-dev` | 执行开发（状态流转；全自动才自动甄别） |
| POST | `/tabs/:id/workflow/triage` | 手动「开始 AI 甄别」 |
| POST | `/tabs/:id/workflow/auto-mode` | 切档 `{ mode: "semi"\|"full" }` |
| POST | `/tabs/:id/workflow/reject` | 确认拒绝 |
| POST | `/tabs/:id/workflow/wiki` | 导出经验到 docs/wiki |
| POST | `/tabs/:id/workflow/claudemd` | 写入工程 CLAUDE.md 已知问题段 |
| GET  | `/tabs/:id/tb-attachments` | 附件清单（含 `confirm` 阈值摘要） |
| POST | `/tabs/:id/tb-attachments/download-batch` | 批量下载（WS 进度） |

### WebSocket 事件
- `chat_stream` / `chat_stream_end` / `chat_message`：对话流式与最终消息。
- `devbench_attach_progress`：附件 `need_confirm` / `file` / `end`。

### 状态机阶段（`tab.workflow.phase`）
`claimed`（待甄别）→ `triaging` → `fixing` / `reject_pending` → `testable`（已提测） / `rejected`（已拒绝）。
