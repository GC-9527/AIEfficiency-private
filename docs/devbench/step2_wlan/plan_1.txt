================================================================================
【方案】阶段1：分布式 agentic —— 中心大脑 + 远端工具执行
分支 feat/lan-distributed-agent
================================================================================

目标：中心机的「大脑(LLM)」做推理，工具(读/写/改文件、跑命令、gradle)在「工程所在的
远端机」本地执行。远端把环境/文件/命令输出作为上下文回传，循环直到完成。
—— 即「Claude/大脑在我这，工程和执行在他们机器上」的真正落地。

────────────────────────────────────────────────
一、关键技术分叉（大脑用什么）
────────────────────────────────────────────────
约束：Claude Code CLI 是「大脑+手脚一体」拆不开，且 CLI 订阅登录无法被远程驱动工具。
要「中心大脑 + 远端工具」，大脑必须是「API 形态的 tool-use 循环」，两个选项：

  A) api-engine（已存在）：OpenAI 兼容（Qwen/Kimi/DeepSeek/OpenAI…）
     - 现成：gateway/services/api-engine.js 已实现 tool-use 循环；
       api-tools.js 已定义工具(read/write/edit/list/bash)。
     - 只需把「工具执行」从本地改成「转发到远端执行器」即可成为分布式 agentic。
     - 代价：大脑不是 Claude（是你配的 OpenAI 兼容模型，需对应 API key）。

  B) Claude API（Anthropic Messages tool-use）：大脑是 Claude
     - 需要 Anthropic API key（与 CLI 订阅是两套计费）。
     - 请求/响应格式与 OpenAI 不同，要新增一个 Anthropic 引擎适配。
     - 这才是「中心大脑=Claude」的唯一正路。

结论：先用 A 打通分布式 agentic 全链路（最快见效、复用现成循环）；
      想要「Claude 当大脑」再加 B（Anthropic 引擎，需 key）。两者共用同一套远端执行器。

────────────────────────────────────────────────
二、总体架构
────────────────────────────────────────────────
  中心机（大脑）
    └─ agent 循环（api-engine：发 messages+tools → 拿 tool_calls → 执行 → 回灌 → 重复）
         · 工具执行不在本地，而是 HTTP 调「目标远端」的 /api/executor/run-tool
         · 目标远端 = 该任务/故事点选定的「远端机 + 工程 root」

  远端机（手脚）——【本阶段已实现 ✅】
    └─ /api/executor  执行器
         · run-tool: 在 root 工程内执行 read_file/write_file/edit_file/list_dir/run_bash
         · 安全：token 鉴权 + root 必在白名单(本机配置工程/克隆目录) + 路径不得越出 root
         · /projects: 本机有哪些工程  /health: 启用状态 + 白名单

循环数据流：
  中心 agent → (tool_call) → HTTP → 远端 /api/executor/run-tool → 本地执行 → 结果回传
            → 中心把结果回灌给 LLM → LLM 决定下一步 … → 完成
