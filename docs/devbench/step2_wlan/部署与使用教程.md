# 服务端 / 客户端 部署与使用教程

本教程介绍**局域网分角色部署**：一台「服务端」集中托管 Claude 能力、共享配置和管理后台；多台「客户端」各自在本机跑开发（gradle/git/adb），AI 与共享配置由服务端统一提供。

> 概念速览见 `局域网分角色部署.md`；本文聚焦"怎么装、怎么配、怎么用"。

---

## 零、先搞懂「网关」与通信链路

### 网关是什么？

**「网关」= 一个用 Node.js 写的本机后端服务程序**（`server.js`），默认监听端口 **3001**。它干所有实际的活：

- 提供 REST API + WebSocket + 本地 SQLite 数据库；
- 真正去调用 Claude / Gemini / Codex（CLI 或 API）跑任务；
- 跑 devbench（工程开发）、executor（本机执行器）、TB 任务、定时任务、设备发现等。

> 它**不是网络路由器**（名字容易误解），就理解成"本机后端服务"。你看到的网页面板只是 **UI 外壳**，自己不干活，所有操作都发给网关。
> 类比：**网页 = 遥控器，网关 = 真正执行的主机。**

### 每台机器都有自己的网关

无论客户端还是服务端，**每台机器都跑一个网关**，区别只是 `role` 决定挂载哪些功能。
**不存在"无本机网关的纯瘦客户端直连服务端"**——因为本机的 gradle/git/adb/devbench/executor 必须在本机网关上跑，这正是"重活各机本地跑、只共享 Claude"的设计目的。

### 通信链路

浏览器/桌面 UI 只跟**自己机器的网关**说话；只有"借服务端的 Claude 做文本/分布式任务"时，才由**客户端网关 → 服务端网关**转发，浏览器**从不直连**服务端。

```
[浏览器 / 桌面 UI] → [本机网关:3001] ──局域网模式──→ [服务端网关:3001] → 服务端的 Claude
     （UI 壳）          （干活的后端）                    （共享 Claude 的那台）
```

本机重活（gradle/git/devbench/executor）都在本机网关跑；只有文本/分布式任务才走到服务端网关。

### API 永远打到 localhost:3001

面板所有 `/api/...` 请求都发给**你自己机器的网关**（默认 `localhost:3001`）。"网页从哪加载"才分两种，但**干活的后端永远是 localhost:3001**：

| | Web 模式 | Desktop 模式 |
|---|---|---|
| 本机网关 | 有（`setup.ps1` 安装的源码网关） | 有（EXE **内置**，启动时自动拉起子进程） |
| 要不要自己装 Node | 要（Node 20+） | **不要**（内置 portable Node） |
| 面板从哪加载 | 云端面板 `:8080` | EXE 内置 / 云端 |
| API 打到哪 | `localhost:3001` | `localhost:3001` |

> Desktop **不是**"没有网关、直接连服务端"——它**内置并自动启动**本机网关，依旧走"本机网关 →（局域网模式）→ 服务端网关"。Desktop 的价值是把 Node + 网关 + 依赖全打包，**双击即用**。

### 谁是客户端、谁是服务端，怎么定？

- **Desktop**：首次启动的模式选择页选「本机角色」——💻 客户端 / 🌐 服务端（共享本机 Claude），一键写入角色，无需懂配置字段。
- **Web 模式 / 后续调整**：设置 → 中心 Claude 代理 → 部署角色（**仅管理员可改**）。

## 一、三种角色

设置 → 「中心 Claude 代理（局域网共享）→ 部署角色」选择，或用环境变量 `ROLE` 覆盖（优先级：`ROLE` > 配置 > 默认 `standalone`）。**改后重启网关生效。**

| 角色 | 适用 | 挂载能力 |
|------|------|---------|
| `standalone`（默认，单机全功能） | 一个人单机用，或先单机体验 | 全部（server + node） |
| `server`（服务端/中心机） | 有 Claude 账号、托管共享配置与管理后台的那台 | Claude 文本代理、分布式编排、管理后台 RBAC、共享配置中心 |
| `node`（客户端/开发机） | 团队成员的开发机 | 本地执行 + 全部开发工具；共享配置/文本任务转发到服务端 |

**关键分工**
- **服务端**存：仓库定义、车型映射、关键词映射、应用分类、TB 项目列表、管理员名单、超管 TOTP 密钥。管理员在服务端改 → 所有客户端实时读到。
- **客户端**留本机：克隆父路径、本地源码 checkout、git clone、设备连接。这些是每台机器各自的。

## 二、准备工作（通用）

1. **网关安装**（三选一）：
   - **桌面版**：安装 `AI提效工具 Setup x.x.x.exe`，内置 Node.js，免依赖。**首次启动选「本机角色」**（💻 客户端 / 🌐 服务端共享 Claude）即自动配好角色，无需懂字段。
   - **Web 模式（中心 Docker）**：在目标机 PowerShell 执行 `irm http://192.168.10.156:8080/setup.ps1 | iex`，会装好本机网关（`localhost:3001`）。
   - **局域网自分发（无中心 Docker，推荐团队内用）**：从**任一台服务端**装客户端 —— 浏览器打开 `http://<服务端IP>:3001/install` 一键装，**自动配成"客户端 + 已连这台服务端"**。详见第「四·补」节。
2. 网关默认端口 **3001**；前端面板桌面版内置，Web 模式从云端面板或**服务端自带面板**访问。
3. 局域网内各机能互通（同网段；服务端防火墙放行 3001）。

## 三、服务端（中心机）部署

> 选一台**有 Claude 账号**、长期开机、网络稳定的机器。

> 以下"中心 Claude 代理"相关项均为**管理员设置**（部署角色 / 对外提供 Claude / 额度 / 后端 / API Key / 对外服务口令 / 执行器），需先在「管理后台」登录后才能改（见第 6 步）。Desktop 首次启动模式选择页选「🌐 服务端」会自动把角色配成 standalone + 开启对外提供 Claude。

1. 装好网关，打开设置。
2. **部署角色** = `服务端`（或先用 `standalone` 单机验证；Desktop 选了服务端则已是 standalone）。
3. **Claude 能力**（二选一）：
   - 订阅 CLI：确保本机已 `claude login`（中心代理后端用「订阅 Claude CLI」）。
   - 合规计费：设置 → 中心 Claude 代理 → 代理后端 = `Anthropic API`，填 `sk-ant-` Key（多人共享更合规，详见下方"防封号"）。
4. **对外提供 Claude 文本代理**：开启；设一个**对外服务口令**（如 `lan-2026`，代理与执行器共用，远端连接要填一致），记住它。可设**最大并发**（同时几个故事点）与**每日 token 额度**（算力上限，用尽则客户端不可连）。
5. **Teambition**：设置 → Teambition 一键登录（扫码）拿 Cookie；「操作的 TB 项目」点「拉取可选项目」勾选要用的项目（支持多项目）。
6. **管理后台**：
   - 设置 → 管理后台：超管登录已是 **TOTP 动态验证码**。
   - 打开「管理后台」页 →「超管验证码」→「首次使用 / 重新绑定验证器」→ 用 Google Authenticator 扫码绑定。密钥存本机 `gateway/.secrets/admin-totp.json`（不进 git）。
   - 用 6 位码登录后，从「组织成员」里把团队管理员加进名单（成员来自 Teambition）。
7. **共享配置**（管理员在服务端配，全员共享）：
   - 工程开发（devbench）→「⚙ 工程配置」：维护**仓库定义**（仓库名 + git ssh，https 自动推断）。
   - 「🚗 车型源码配置」：配 **车型 → 应用 → 仓库 + 分支 + flavor**。
   - 「🔑 关键词映射设置」：同步项目/迭代/标签 key，把它们映射到 应用/车型（标题关键词由"执行开发"自动采集）。
8. 重启网关。记下服务端**局域网 IP**（如 `192.168.10.50`）+ 端口 `3001`。

## 四、客户端（开发机）部署

> 每个团队成员的开发机。

1. 装好网关（Desktop 首次启动模式选择页选「💻 客户端」即自动配好角色），打开设置。
2. **部署角色** = `客户端节点`（Desktop 选了客户端则已是此角色）。
3. **本机运行模式**（设置 → 中心 Claude 代理 → 「本机运行模式」，**普通用户即可改，不需管理员**）：
   - 选 **借用其它服务端的 Claude**；
   - **连接口令** 填与服务端「对外服务口令」**一致**的口令（如 `lan-2026`）；
   - 在下方「🖥 选择服务端」列表里点目标服务端的「连接」——同子网会**自动出现**（按算力排序，满载禁选）；跨子网则在框里手填 `http://<服务端IP>:3001`（如 `http://192.168.10.50:3001`）「＋ 添加」后再连接。
   - 「默认引擎」选 **中心 Claude 代理**（报告/总结等文本任务走所连服务端的 Claude）。
   - 若本机想**直接用本机 Claude**（不借局域网），运行模式选「用本机 Claude」即可。
4. **Teambition**：本机也一键登录拿自己的 Cookie（用于看自己的任务、扫码登录管理后台）。
5. **本机路径**：工程开发 →「🚗 车型源码配置」里设**克隆父路径**（如 `D:\workspace\xsProjects`，每台机器各自设）。
6. 重启网关。

> 客户端的「工程配置 / 车型 / 关键词映射」会**自动读服务端的共享配置**——只读管理员配好的那套，本机不用重复维护。

## 四·补、局域网自分发（无中心 Docker，一键装客户端）

如果你们**没有中心 Docker**（或新设备够不到那台 `192.168.10.156:8080`），可以让**任一台服务端自己分发客户端**——服务端角色（server/standalone）的网关自带分发能力。

### 用法（在要装客户端的设备上）

浏览器打开 **`http://<服务端IP>:3001/install`**（端口 3001），落地页提供三种方式 + 一个**二维码**（手机扫码可在其它设备打开本安装页）：

| 入口 | 傻瓜度 | 说明 |
|------|--------|------|
| ① **下载桌面版 EXE（Windows）** | ★★★ 最傻瓜 | 双击装，内置 Node + 网关 + 面板；首次启动选「💻 客户端」，「选择服务端」里自动发现本服务端。**需管理员先在服务端放置 EXE**（见下）。EXE 仅 Windows，macOS 用 ②/③ |
| ② **直接用网页版**（全平台） | ★★ | 服务端自带面板，点「打开网页面板」即用；面板里网关地址填 `http://localhost:3001` |
| ③ **命令行一行命令**（Windows / macOS / Linux） | ★ | Windows：`irm http://<服务端IP>:端口/setup.ps1 \| iex`；macOS/Linux：`curl -fsSL http://<服务端IP>:端口/setup.sh \| bash` |

③ 的脚本会自动：装 Node（Windows 缺则 winget，macOS 缺则提示 `brew install node`）、下载并安装网关、注册开机自启（Windows 计划任务 / macOS launchd）、启动，并**自动把本机配成「客户端(role=node) + 已连这台服务端」**——开发者零配置。
> Windows 若提示执行策略限制：先 `Set-ExecutionPolicy -Scope Process Bypass -Force` 再粘贴。
> 只想装网关、不自动配客户端：命令后加 `?client=0`（如 `…/setup.sh?client=0`）。
> 端口即服务端网关端口（默认 3001，本机若跑在 3002 则用 3002，落地页命令已自动带上）。

### 服务端侧准备

- **命令行 / 网页版**：开箱即用（`gateway-bundle.zip` 由服务端按需现打）。网页版需服务端有前端构建产物（源码部署先在 `web-dashboard` 跑一次 `npm run build`；桌面版自带）。
- **桌面版分发（Windows / macOS）**：把安装包放到服务端的 `gateway/desktop-setup.exe`、`gateway/desktop-setup.dmg` 或 `desktop/dist/`（包较大，仓库不含，需构建/拷贝一次）。落地页 ① 按平台显示对应下载按钮，未放置的平台显示"未就绪"，不影响 ②③。
  - Windows 包：`cd desktop && npm run dist:win`。
  - **macOS 包**：必须在 **Mac 上**构建（`better-sqlite3` 与 dmg 工具均需 macOS）：先 `cd gateway && npm install`（得 mac 预编译原生模块），再 `cd desktop && npm install && npm run dist:mac` → 产出 `desktop/dist/*.dmg`（arm64 + x64）。mac 桌面版**用系统 Node**，目标机需装 Node 20+（`brew install node`）；首次打开被 Gatekeeper 拦时右键「打开」或 `xattr -dr com.apple.quarantine /Applications/AI提效工具.app`。
- 关闭自分发：设置项 `servers.distribute=false`（默认开）。

### 与中心 Docker 的区别

中心 Docker（`:8080`）是**集中**分发 + 托管面板；本节是**每台服务端自给**分发，适合纯局域网、无中心服务器的团队。两者可并存。

## 五、验证部署

**服务端**（浏览器或 curl）：
```
GET http://<服务端IP>:3001/api/claude-proxy/health   → {ok:...}   # 代理可用
GET http://<服务端IP>:3001/api/devbench/project-defs  → 仓库列表    # 共享配置在
```
**客户端**：
```
GET http://localhost:3001/api/devbench/project-defs    → 应与服务端一致（已转发到中心）
GET http://localhost:3001/api/devbench/remote-config    → 车型来自中心，cloneParent 是本机
```
若客户端的仓库/车型/关键词与服务端一致，说明中央转发已生效。

## 六、日常使用

### 管理员（在服务端）
- 加/改 **仓库**、**车型映射**、**关键词映射**、**TB 项目** → 全员实时生效。
- 「管理后台」管理管理员名单（从 Teambition 成员里选）。
- 关键词映射里修正 AI 识别（如 `阿维塔_8678`→车型 `avatr8678`、`应用市场`→应用 `App Market`）。

### 开发者（在客户端）
1. devbench 顶部若有多个项目，先用**项目下拉**切到目标项目。
2. **从 TB 任务执行开发**：任务列表点「执行开发」→
   - 自动采集该 TB 标题的 `【】` 关键词到中心，并按映射**识别默认应用/车型**；
   - 有该工程本地源码 → 进「本地工程」模式选源；没有 → 进「远程拉取」，选车型/分支后点「开始初始化工程」克隆到 `克隆父路径\车型\年月\仓库名-单号`。
3. **新建故事点**：「＋ 新故事点」可「选择工程新建」（有本地源码进本地、无则远程拉取）。
4. 拉取过的本地源码会**记录在本机**，下次同仓库+分支可直接复用。
5. 开发对话、跑 gradle/git/adb 都在**本机**；周/月报等文本任务走**中心的 Claude**。

## 七、防封号（重要）

中心代理默认用**本机订阅 Claude CLI**：不转发凭证、不反代 API，对 Anthropic 而言是单机单号官方 CLI。但"一个订阅多人用"属个人条款灰色地带，量大可能触发滥用检测。

- 合规做法：设置 → 中心 Claude 代理 → 代理后端 = **Anthropic API** + 填 `sk-ant-` Key（官方按量计费，单账号多人服务合规）。
- 选了 api 但没填 Key 会**自动回落 CLI**。

## 八、常见问题

- **客户端配置和服务端不一致？** 确认客户端角色=节点、运行模式=借用服务端、已在「选择服务端」里连上目标服务端且连接口令与服务端「对外服务口令」一致、服务端在线；共享配置是转发读取的。
- **客户端为什么没有「管理后台」入口？** 正常——客户端（node）不挂管理后台，面板会**按所连网关角色自动隐藏**该入口。局域网/共享账号设置请到**服务端机器的面板**由管理员管理；客户端只做本机模式切换 + 选服务端（都不需要管理员）。
- **客户端的部署角色/对外共享/执行器为什么改不了（置灰）？** 这些是管理员/集群级设置。客户端的角色在**安装时**（Desktop 模式选择页）设定；要改请在服务端面板由管理员操作，或把该机改成 standalone 后用管理员登录。
- **超管验证码登录失败？** 旧密钥若被换过需重新绑定；在「管理后台」登录页「重新绑定验证器」重扫一次（密钥在网关本机）。
- **成员/应用分类拉不到？** 需有效的 Teambition 登录态；按提示扫码登录后重试。
- **改了部署角色没生效？** 角色改动需**重启网关**。
- **克隆父路径是全局还是按项目？** 是**本机全局**（每台机器一个），不随项目切换。
