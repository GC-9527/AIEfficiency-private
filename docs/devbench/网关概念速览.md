# 网关概念速览（1 分钟搞懂）

> 完整部署/使用见 `step2_wlan/部署与使用教程.md`。本页只讲"网关是什么、怎么连"。

## 网关是什么？

**网关 = 一个用 Node.js 写的本机后端服务程序（`server.js`，默认端口 `3001`）。** 它干所有实际的活：

- REST API + WebSocket + 本地 SQLite 数据库；
- 真正调用 Claude / Gemini / Codex（CLI 或 API）跑任务；
- 跑 devbench（工程开发）、executor（本机执行器）、TB 任务、定时任务、设备发现等。

> 它**不是网络路由器**（名字易误解），就是"本机后端服务"。网页面板只是 **UI 外壳**，自己不干活，所有操作都发给网关。
> 类比：**网页 = 遥控器，网关 = 真正执行的主机。**

## 每台机器都有自己的网关

无论客户端还是服务端，**每台机器都各跑一个网关**，区别只是部署角色 `role` 决定挂载哪些功能：

| 角色 | 挂载 | 谁用 |
|------|------|------|
| `standalone`（默认） | 全部（server + node） | 单机 / 服务端机 |
| `server` | Claude 文本代理 + 分布式编排 + 管理后台 | 共享 Claude 的中心机 |
| `node` | 本地执行 + 全部开发工具（无管理后台、无对外 Claude） | 开发机/客户端 |

**不存在"无本机网关的瘦客户端直连服务端"**——本机的 gradle/git/adb/devbench 必须在本机网关上跑，这正是"重活各机本地跑、只共享 Claude"的目的。

## 通信链路

浏览器/桌面 UI 只跟**自己机器的网关**说话；只有"借服务端 Claude 做文本/分布式任务"时，才由**客户端网关 → 服务端网关**转发，浏览器**从不直连**服务端。

```
[浏览器 / 桌面 UI] → [本机网关:3001] ──局域网模式──→ [服务端网关:3001] → 服务端的 Claude
     （UI 壳）          （干活的后端）                    （共享 Claude 的那台）
```

## 两种部署（都有本机网关，API 都打 localhost:3001）

| | Web 模式 | Desktop 模式 |
|---|---|---|
| 本机网关 | 有（`setup.ps1` 装的源码网关） | 有（EXE **内置**，启动自动拉起子进程） |
| 要不要自己装 Node | 要（Node 20+） | **不要**（内置 portable Node） |
| 面板从哪加载 | 云端面板 `:8080` | EXE 内置 / 云端 |
| API 打到哪 | `localhost:3001` | `localhost:3001` |

> Desktop **不是**"没有网关、直接连服务端"——它内置并自动启动本机网关，依旧走"本机网关 →（局域网模式）→ 服务端网关"。Desktop 的价值是把 Node + 网关 + 依赖全打包，**双击即用**。

## 角色怎么定

- **Desktop**：首次启动模式选择页选「本机角色」——💻 客户端 / 🌐 服务端（共享本机 Claude），一键写好，无需懂字段。
- **Web / 后续调整**：设置 → 中心 Claude 代理 → 部署角色（**仅管理员可改**）。
