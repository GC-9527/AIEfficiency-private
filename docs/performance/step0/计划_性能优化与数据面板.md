## 二、性能指标体系（R2：补充"稳定性/内存/启动"之外的维度）

在你已有的 3 个维度上补齐为 **11 大维度**（合并 answer_0 建议 + 已落地报告口径）：

| 维度 | 关键指标 | 采集方式 | 优先级 |
|------|---------|---------|-------|
| **启动性能** ⭐ | 冷/温/热启动、①MainActivity 首帧、②配置等待、③HomeActivity 首帧、首页可交互 | 手动埋点 + ASM 注入 Activity 生命周期 | P0 |

| **内存** ⭐ | PSS、Java Heap、Native Heap、GC 次数、OOM、泄漏 | Debug.MemoryInfo 采样 + Runtime | P0 |
| **网络** | 请求耗时、DNS/TLS/首字节分段、失败率、重试 | OkHttp EventListener（已有 NET_TIMING 雏形） | P0 |
| **CPU** | 进程 CPU、主线程耗时、峰值 | /proc 采样 | P1 |
| **UI 流畅度** | FPS、掉帧、卡顿帧、页面渲染耗时 | Choreographer FrameCallback | P1 |
| **I/O** | 文件/DB/SharedPreferences 耗时 | ASM 注入 Room/SP/File | P1 |
| **线程** | 线程数、线程池阻塞、死锁、主线程阻塞 | 线程快照采样 | P2 |
| **包体积** | APK/dex/so/资源大小 | 构建期 Gradle task 统计 | P2 |
| **功耗** | WakeLock、CPU 唤醒（车机弱诉求） | 系统 API | P3 |
| **业务性能** | 首页加载、配置接口、图片下载等业务点 | 手动埋点 | P1 |

## 三、工程 A 改动：性能追踪 SDK（`2026AppMarketAIV5`）

### 3.1 模块拆分（R3：封装成模块）

在工程 A 的 `sdk/internal/infra/` 下新增（与现有 `app-log-*` / `app-database-*` 同级，复用 convention 插件风格）：

| 模块 | 职责 | 依赖 |
|------|------|------|
| `perf-tracker-api` | 埋点接口 `PerfTracker`、注解 `@TracePerf`、指标数据模型 | 无（纯接口，业务可零成本依赖） |
| `perf-tracker-impl` | 各维度采集器实现、本地聚合 | api、app-log、app-data-persist(MMKV) |
| `perf-tracker-reporter` | 本地缓存（Room 表或 JSON 文件）+ 批量 HTTP 上报 | impl、app-net-core(OkHttp) |
| `perf-tracker-gradle-plugin` | ASM 插桩 + DSL 扩展（编译期） | 放 `build-logic`，用 AGP Instrumentation API |

> 设计原则：**关闭时零成本**——api 是空壳接口，impl 在 DSL 关闭时不参与插桩、运行时走 No-Op 实现。

### 3.2 埋点 API（手动埋点，R3）

```kotlin
PerfTracker.start("cold_start")
PerfTracker.mark("application_onCreate")
PerfTracker.mark("main_activity_first_frame")   // ① 终点
PerfTracker.mark("home_activity_start")          // ② 终点
PerfTracker.end("cold_start")                    // ③ 首帧

PerfTracker.page("HomeActivity").start()/firstDraw()/interactive()
PerfTracker.network(url, dns, tls, firstByte, total, success, code)
```

### 3.3 双层开关：编译期 Gradle + 运行期 AppMockData（R4，**Release 也能开**）

> **本节按你的要求调整**：原"Release 默认关、只靠 Gradle 编译期开关"改为——**Release 包同样编译进性能采集能力，靠运行时开关控制是否真正采集/上报**，运行时开关挂在 `AppMockData` 上。这样无需重新出包，就能在车机上对 Release 包临时开启性能分析。

采用**两层开关**，职责分明：

#### 第 1 层（编译期）：Gradle DSL —— 是否把采集代码"编进包里 / 是否插桩"

在 app `build.gradle.kts` 暴露 DSL（由 `perf-tracker-gradle-plugin` 提供）：

```kotlin
performanceTracker {
    enable = true                  // 编译期总开关：true=插桩并编入(含 Release)；false=彻底不插桩、运行时 No-Op
    enableAop = true               // ASM 字节码插桩开关
    enableStartupTrace = true
    enablePageTrace = true
    enableNetworkTrace = true
    enableDbTrace = true
    enableMethodTrace = false      // 全方法耗时（默认关，开销大）
    reportEndpoint = "http://<AIEfficiency网关>/api/performance/ingest"
    reportDir = "$buildDir/performance-report"
    sampleRate = 1.0               // 采样率
}
```

- **默认 Debug 与 Release 都 `enable = true`**（编进去），是否采集交给第 2 层运行时开关；真正的出厂量产包若要彻底剔除，再单独把 `enable=false`（插桩 transform 直接 return 原字节码、运行时切 No-Op、零成本）。
- 可按 flavor 差异化（avatr8678 / gwmx9 等单独配置）。

#### 第 2 层（运行期）：`AppMockData` 开关 —— Release 上也能动态开/关

复用工程 A 已有的 Mock 配置下发通道：mock app（`app-mock-app` 的 `MainActivity` / `AppMockService`）把配置广播出去，主 App 通过 `AppMockSdk.observeAppMockData()` 实时订阅。在 `AppMockData` 上新增性能开关字段，即可在 **Debug 和 Release 上都通过 mock app 动态切换**，无需重新打包。

- **新增字段位置**：`AppMockData` 数据类——`app-mock-sdk/src/main/java/com/appmarket/automotive/mock/AppMockData.kt`（注意：你提到的是 `app-mock-app`，但数据类实际定义在同目录树的 `app-mock-sdk`；**切换 UI** 才在 `app-mock-app` 的 `MainActivity`/`AppMockService`，两个模块都要改）。
- **建议新增字段**（带默认值，保证向后兼容、不破坏现有构造点）：

```kotlin
data class AppMockData(
    /* …现有字段… */
    val serverDisplayId: String = "",
    // —— 新增：性能分析运行时开关（Release 也生效）——
    val perfTrackerEnabled: Boolean = false,   // 运行时总开关：true 才真正采集+上报
    val perfReportEnabled: Boolean = true,     // 是否上报到 AIEfficiency（false=只本地采集）
    val perfSampleRate: Float = 1.0f,          // 运行时采样率
    val perfReportEndpoint: String = ""        // 可选：运行时覆盖上报地址，便于现场指向某台网关
)
```

- **生效逻辑**：`PerfTracker` 初始化后订阅 `observeAppMockData()`；只有 `第1层 enable=true（编进包） && perfTrackerEnabled=true` 时才真正采集；`perfReportEnabled` 控制是否上报；地址优先取 `perfReportEndpoint`（非空时覆盖 Gradle 的 `reportEndpoint`）。
- **改动点清单**：
  1. `app-mock-sdk` 的 `AppMockData` 加字段 + `AppMockSdk` 的序列化/反序列化（`getAppMockData()`、observe 解析处）带上新字段；
  2. `app-mock-app` 的 `MainActivity`/`AppMockService` 增加"性能分析"开关 UI（开/关 + 采样率 + 上报地址输入），下发时写入；
  3. 主 App 侧 `perf-tracker-impl` 订阅并应用该开关。

> 价值：现场/测试在 **Release 包**上，用 mock app 一键开启性能分析、指定上报到某台 AIEfficiency 网关，跑完即关，无需重新构建安装。

### 3.4 AOP / 插件注入（R5：插件 + 面向切面）

三层注入，与 answer_0 一致：

| 层 | 技术 | 注入对象 |
|----|------|---------|
| 手动 | `PerfTracker.start/end` | 核心业务流程 |
| 注解 AOP | `@TracePerf("name")` | 方法耗时、关键函数 |
| **字节码插桩** | **ASM + AGP Instrumentation API**（`perf-tracker-gradle-plugin`） | Activity/Fragment 生命周期、OkHttp 调用、Room DAO、点击事件——**自动注入，无需改业务代码** |

> 选 ASM + AGP Instrumentation API（非 AspectJ）：与工程 A 现用的 AGP 8.9.1 / KSP / convention 插件体系最契合，编译增量友好。

### 3.5 数据采集与本地存储

- 启动/页面/网络：插桩 + 埋点回调写入内存聚合器。
- 内存/CPU/线程/FPS：后台采样线程定时快照（压测期间）。
- Crash/ANR：全局 `UncaughtExceptionHandler` + ANR 监控（主线程喂狗）。
- **本地兜底**：弱网/离线先写本地（Room 表或 `reportDir` 下 JSON），联网后补传——保证车机断网也不丢数据。

### 3.6 上报模块（R10：像友盟 / GA 一样上报）

- **上报结构**（一次会话一份，含设备/版本/场景标识，便于面板分组）：

```json
{
  "sessionId": "uuid",
  "appVersion": "4.x.x",
  "flavor": "avatr8678",
  "deviceId": "car_xxx", "deviceModel": "gwmx9",
  "scenario": "cold_start",
  "round": "round_007",            // 关联 Monkey 轮次
  "startup": { "stage1Ms": 802, "stage2Ms": 1519, "stage3Ms": 236, "totalMs": 2557,
               "refreshAppConfigMs": 1680, "dnsMs": 18, "tlsMs": 338 },
  "memory": { "pssMb": 180, "javaHeapMb": 90, "gcCount": 5 },
  "metrics": [ { "name": "getHomeData", "cost": 433 } ],
  "events": [ { "type": "crash|anr|jank", "detail": "...", "ts": 1710000000 } ]
}
```

- **上报时机**：会话结束 / 退后台 / 批量定时；失败重试 + 本地补传。
- **传输**：OkHttp `POST` 到 DSL 里配的 `reportEndpoint`；与友盟同理——SDK 只管"采集 + 缓存 + 批量上报"，分析在服务端（AIEfficiency）。

## 四、工程 B 改动：AIEfficiency 数据面板（R9）

### 4.1 接入层（ingest，对应 R10）

新增 `gateway/routes/performance.js`，在 `server.js` 挂载 `app.use("/api/performance", performanceRouter)`：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/performance/ingest` | 接收车机上报（单条或批量），入库 + WS 广播 |
| GET | `/api/performance/sessions` | 会话列表（按 flavor/device/scenario/round 过滤） |
| GET | `/api/performance/metrics` | 指标查询（趋势、聚合） |
| GET | `/api/performance/rounds` | Monkey 轮次列表（用于版本/轮次对比） |
| POST | `/api/performance/analyze` | 触发 AI 分析某轮/某会话，产出建议 |
| GET | `/api/performance/report/:id` | 取 AI 分析报告 |

### 4.2 存储（`gateway/db/sqlite.js` 新增表）

沿用项目现有 `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE` 迁移模式：

- `perf_session`：一次启动/会话（设备、flavor、版本、场景、round、各阶段汇总耗时）
- `perf_metric`：会话下的细分指标（name / value / unit）
- `perf_event`：crash / anr / jank / 慢方法 事件
- `perf_round`：Monkey 一轮的元信息（事件数、崩溃数、ANR 数、起止时间、基线对比）
- `perf_report`：AI 分析结果（输入轮次、结论、恶化项、根因、优化建议、下一轮建议）

### 4.3 面板页面（`web-dashboard/src/pages/Performance.jsx`）

在 `App.jsx` 侧栏新增「性能」入口（路由 `/performance`）。引入轻量图表库 **recharts**（当前无图表库，需 `npm i recharts`）。模块：

| Tab | 内容 |
|-----|------|
| **总览** | 启动时间 / Crash / ANR / 内存 / CPU / 卡顿趋势曲线 + 阈值红线 |
| **启动分析** | ①②③ 三段堆叠柱 + `refreshAppConfig`/DNS/TLS 子项，复现报告主表 |
| **性能日志** | 原始上报会话 + 事件流（crash/anr/jank），可搜索筛选（R9 "性能日志"） |
| **Monkey 报告** | 每轮事件数/崩溃/ANR、本轮 vs 上一轮 vs 基线 |
| **版本/轮次对比** | round_001 … round_N 性能变化对比 |
| **AI 分析** | AI 结论、恶化项、根因、优化建议、下一轮建议（R7/R9） |

- 实时：复用现有 WebSocket（`/ws`），ingest 后广播 `performance_update`，面板自动刷新。

### 4.4 AI 分析（R7）

复用 `gateway/services/agent-runner.js`：`/api/performance/analyze` 组装 prompt（本轮报告 + 上一轮报告 + 启动日志摘要 + Monkey 日志 + Crash/ANR + 最近 git diff）→ 调引擎 → 结构化结果存 `perf_report`。可新增一个 `/perf-analyze` skill 固化分析口径（输出：是否变好 / 恶化项 / 根因 / 优化代码位置 / 优先级 / 下一轮建议）。

## 五、Monkey + AI 闭环流水线（R6 / R8）

                --pct-touch 40 --pct-appswitch 10 --ignore-crashes -v <N>

## 八、风险与注意

1. **运行时默认关、零成本**：Release 包虽编入采集能力（`enable=true`），但运行时 `perfTrackerEnabled` 默认 `false`，正常用户不触发采集；真正量产剔除用 DSL `enable=false`（插桩与运行时完全旁路）。注意 ProGuard/R8 规则要 keep 住 `PerfTracker` 与 `AppMockData` 新增字段，避免 Release 混淆/裁剪掉。
2. **多 flavor 兼容**：工程 A 有 7+ flavor，埋点与上报要带 flavor 标识；插桩需在所有 flavor 验证。
3. **f515R 加密日志（ELOG）**：现状黑盒，补埋点是首要价值（报告 §3.5 已指出）。
4. **车机隐私/合规**：上报仅含性能与设备型号，不含用户数据；可配置上报地址、采样率、仅压测包上报。
5. **AI 自动改代码风险**：闭环第一版只自动到"分析建议"，代码修改人工确认，防止误改车机核心路径。
6. **同步规则**：工程 B 网关代码改动后需同步到 `desktop/gateway-bundled`（见项目记忆约定）。
