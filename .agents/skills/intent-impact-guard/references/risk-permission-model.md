# 风险与权限模型

## 风险等级

### LOW

- 单一页面/组件内的附加式改动；
- 不改变路由语义、权限、公共 API 或共享数据；
- 可由一个目标测试覆盖；
- 回滚只需撤销局部 diff。

最低证据：1 条 VERIFIED；至少 2 个简洁候选方案。

### MEDIUM

- 新增或修改路由、共享 UI、状态管理、错误处理；
- 多文件或多个调用方；
- 影响多个断点、Variant 或普通/管理员角色；
- 仍保持公共合同和安全边界。

最低证据：2 条 VERIFIED，至少覆盖入口和行为实现；必须列出关联回归面。

### HIGH

- 登录、认证、授权、角色模型；
- 公共 API/SDK、模块职责或数据源迁移；
- 删除旧能力、Mock、兼容层；
- 多仓、多车型、多 Flavor 共享实现；
- 新生产依赖或大范围架构重构。

最低证据：3 条 VERIFIED，覆盖当前合同、调用方和验证；需要明确授权或保持只读。

### CRITICAL

- 生产数据、密钥、支付、隐私、安全策略；
- 部署、发布、远端不可逆状态；
- 数据库破坏性迁移、删除远端分支/资源；
- 无法可靠回滚的操作。

默认只读。必须有明确、可审计授权、备份、演练和回滚步骤。

## 权限等级

权限不能由任务目标隐式推导，必须显式记录。

| 权限 | 允许 | 默认禁止 |
|---|---|---|
| READ_ONLY | 搜索、读取、分析、无副作用测试 | 修改文件、推送、发布 |
| LOCAL_WRITE | 当前工作树编辑、本地构建测试 | 远端写入、删除共享资源 |
| EXTERNAL_WRITE | 已授权的 push/MR/工单回写/发布 | 超出指定目标的任何外部操作 |
| DESTRUCTIVE | 已授权的不可逆操作 | 一切未逐项授权的破坏性动作 |

## 风险提升信号

出现任一项至少提升一级：

- 修改共享基类、公共组件、路由守卫、认证中间件；
- 引入新依赖或权限；
- 涉及多个 Flavor/车型/平台；
- 当前工作树有无关未提交改动；
- 缺少测试环境或无法运行关键验证；
- 文档与代码冲突；
- 需要绕过现有保护才能“让功能工作”。

## 风险降低条件

只有真实证据可降低风险：

- 已有同类模式和稳定测试；
- 变更是向后兼容的可选能力；
- 目标行为可在隔离环境中复现和验证；
- 回滚路径已验证；
- 改动被明确限制在 canonical 源和单一职责边界内。
