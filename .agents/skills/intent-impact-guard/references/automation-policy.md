# 自动化、Token 与停止策略

## FAST 模式

适用：LOW 风险、局部附加式改动、现有模式明确。

预算：

- 读取 1–3 个核心文件和直接测试；
- 2 个候选方案可各一行；
- 只运行目标测试和一个代表性回归；
- 不输出长报告。

## STANDARD 模式

适用：MEDIUM 风险、共享 UI/状态、路由、多 Variant。

预算：

- 入口、实现、直接调用方、测试；
- 明确回归半径和改动预算；
- 目标测试 + 受影响模块构建/集成检查。

## CONTROLLED 模式

适用：HIGH/CRITICAL。

要求：

- 完整合同、调用方、权限、迁移和回滚证据；
- 明确授权；
- 独立审查；
- 不能验证时保持只读。

## Token 优化

- 先用搜索定位符号，再读局部上下文；
- 机械事实由脚本输出；
- 只加载当前领域 reference；
- 用结构化短字段代替长篇“思考过程”；
- 证据变化前不重复全仓扫描；
- 报告只引用关键 diff、命令与结论。

## 停止条件

出现以下任一项立即停止写入：

- 状态不是 PREWRITE READY；
- 需要预算外模块；
- 风险提升到 HIGH/CRITICAL 且无授权；
- 关键测试无法运行或持续失败；
- 当前 HEAD/Dirty Patch 与记录不一致；
- 发现并发 Agent 正在写同一工作树；
- 方案会产生禁止结果。
