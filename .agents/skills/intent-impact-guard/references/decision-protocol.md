# 决策协议详解

## 1. 三层语义

任何开发请求先拆为三层：

1. **现象（Signal）**：用户看到或感受到的问题，如“没有入口”。
2. **目标（Goal）**：用户真正想完成的业务结果，如“未登录用户可以进入认证流程”。
3. **方案（Solution）**：具体实现，如“新增导航按钮 + `/login` + redirect”。

只有用户明确指定、且不与现有架构冲突时，方案才是硬约束。否则 AI 负责用证据选择方案，而不是把最先想到的实现当需求。

## 2. 事实固定顺序

按以下顺序读取，避免全仓扫描浪费 Token：

1. 项目规则和目标模块 README/架构文档；
2. 用户提到的页面、类、接口、路由；
3. 它们的直接调用方、被调用方和测试；
4. 当前 Git diff、分支、Flavor/Variant；
5. 只有发现共享合同或高风险时才扩展到跨模块/跨仓影响。

若证据互相冲突，优先级为：当前可执行行为/测试结果 > 当前代码与配置 > 当前 diff > 版本化架构文档 > 历史报告 > 聊天记忆。

## 3. 方案比较矩阵

每个候选方案按 0–5 评分；无需展示复杂计算，只需保留结论依据。

| 维度 | 越高越好 | 权重 |
|---|---:|---:|
| 业务目标满足度 | 是 | 5 |
| 不变量保持度 | 是 | 5 |
| 安全与权限正确性 | 是 | 5 |
| 可逆性 | 是 | 3 |
| 与现有架构一致性 | 是 | 4 |
| 回归可验证性 | 是 | 3 |
| 爆炸半径 | 否 | 4 |
| 迁移/兼容成本 | 否 | 3 |
| 新增重复实现 | 否 | 5 |

当两个方案接近时，选择附加式、可回滚、无需迁移现有职责的方案。

## 4. 改动预算

PREWRITE 必须声明预算：

- 允许修改的模块和文件范围；
- 允许新增的路由/API/依赖；
- 明确禁止触碰的模块；
- 预计测试范围；
- 是否允许格式化、重命名、迁移或删除。

实现中出现预算外文件时：

- 若只是生成文件或锁文件，先确认是否由正式构建链产生；
- 若影响共享合同、权限或新的模块，立即回到 PREWRITE；
- 不得用“顺便修复”扩张范围。

## 5. 安全默认策略

### 可以自动决策

- 在已有登录页旁新增可发现入口；
- 给受保护路由补充保持原 URL 语义的跳转；
- 在公共组件内用向后兼容方式增加可选能力；
- 为现有行为补测试、错误提示或空态；
- 修复局部布局但不改变公共布局合同。

### 必须阻断写入

- 改变认证/授权模型；
- 把已有页面重新定义为另一类页面；
- 删除或迁移公共 API、SDK、数据、Mock；
- 改动生产部署、密钥、远端分支或工单状态；
- 无法确认 canonical 源却准备复制代码；
- 用户要求与明确架构不变量直接冲突。

阻断输出只包含：事实、冲突、一个必要决策、两种后果；不要产生长篇追问。

## 6. 重新规划触发器

以下任一发生时，原 PREWRITE 失效：

- 真实调用链与假设不一致；
- 需要修改预算外模块；
- 发现新的角色/Flavor/车型/KMP source set；
- 测试暴露现有行为合同；
- diff 出现生成源码、复制源码或权限变化；
- 用户在执行中改变目标或非目标。

重新规划时只更新变化部分，不重复整仓扫描。
