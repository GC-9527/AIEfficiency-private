# 正例与反例

## 例 1：没有登录入口

### 错误

- 搜到 `/admin`；
- 直接把管理后台页面替换为账号密码表单；
- 后台路由、导航和权限行为被破坏。

### 正确

- 现象：用户找不到认证入口；
- 目标：未登录用户可以进入认证流程；
- 证据：已有 `/login`、AuthGuard 和 `/admin` 业务页面；
- 不变量：`/admin` 保持管理后台职责且需要管理员权限；
- 方案 A：导航增加登录按钮，Guard 跳 `/login?redirect=/admin`；
- 方案 B：把 `/admin` 改成登录页；
- 选择 A：附加式、可逆、职责清晰；B 因职责迁移被拒绝。

## 例 2：国家码统一由 SDK 提供

### 错误

- 删除 App 层 AppMock 国家码；
- 自动化测试失去模拟不同国家的能力。

### 正确

- 目标：生产国家码的 canonical 数据源迁入 SDK；
- 不变量：AppMock 仍可覆盖/注入测试国家码；
- 方案：定义统一接口，生产实现委托 SDK，Mock 实现继续注入；
- 验证真实 SDK 与 Mock 两条路径。

## 例 3：增加 AppMock 通用能力

### 错误

- 只在 `baicn5` Flavor 中复制实现。

### 正确

- 先确认能力是否所有车型共用；
- 通用接口和实现进入共享模块；
- 车型差异通过配置或厂商 adapter；
- 构建目标 Flavor 和至少一个共用实现的代表 Flavor。

## 例 4：修复 UI 遮挡

### 错误

- 给当前按钮设置更大 z-index 和绝对定位；
- 其他分辨率、弹窗和导航被覆盖。

### 正确

- 检查容器布局、overflow、sticky/fixed、共享组件引用点；
- 用符合布局职责的最小修复；
- 验证目标页、一个关联页、窄屏、桌面、缩放和弹窗状态。

## 例 5：应用市场中旧 SDK 代码有 BUG

### 错误

- 直接改应用壳中的旧 SDK 源码；
- 另一个分支再复制一份修复。

### 正确

- 定位 `sdk-api` 和唯一 `sdk-xxx-impl`；
- 确认目标 Flavor 当前依赖路径；
- 在 canonical impl 修复并发布/源码引用；
- 应用工程只更新正式依赖；
- 编译 SDK 和真实应用调用方。

## 例 6：简单局部问题

用户说“设置页缺少退出按钮”，代码证明已有 logout service、其他页面有统一按钮组件，且目标页只缺入口。

可用 FAST 模式：列两个简洁方案，选择复用统一组件的附加式修改，执行目标组件测试与权限/导航验证。无需扫描整个仓库，也无需架构重构。
